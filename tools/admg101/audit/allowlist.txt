# Reviewed on recipe 35 build-7 (source d4483f35, ROM SHA-1 e95b049d) for F7.1. Known limits named here are the ones
# ADMG-101's docs/admg101-dynamic-content.md records; an entry is never added for a content capacity problem without a reason.

[reasons]
debug-menu: The debug menu (debug.c, battle_debug.c, the sprite visualizer) keeps GBA widths for its value entry and list items: a development tool, recorded as a known limit.
frontier-index: Battle Frontier, Battle Dome, Trainer Hill and Trainer Tower trainer and Pokémon-set indices index the facility's own tables, not registry content (known limit: Battle Frontier trainer indices keep GBA widths). domeMonIds is typed enum Species in recipe 35 but holds frontier set indices.
player-trainer-id: The player's or an OT's trainer ID (bytes, halves or the 4-byte array of SaveBlock2, mail, records, TV shows, Walda's phrase), not a content trainer ID.
rematch-matchcall: Rematch and Match Call static tables name base trainers by 16-bit ID (known limit: added trainers have no rematches or calls); availabilityFlag is a flag ID.
apprentice-species-index: The apprentice's speciesIds are indices into its own option list, not species IDs.
decoration-id: Decoration IDs: decorations are not a content registry (DecorationAdd takes a u8 decoration).
ball-enum: Poké Ball IDs (enum PokeBall, 28 balls) are not a content registry; the battle result keeps a byte.
object-event-graphics: Object-event graphics IDs keep their 16-bit width (known limit); a follower's or weather form's overworld species is stored as a graphics ID.
base-dex-bounded: The Pokédex screens and the credits list base National Pokédex numbers only, bounded by NATIONAL_DEX_COUNT (known limit: added species are counted and flagged but not listed).
base-count-bounded: The value is clamped below a base-game count before it is narrowed (type icon animation: type < NUMBER_OF_MON_TYPES, else TYPE_MYSTERY).
wireless-link: Union Room trade-board fields keep the wireless adapter's 384-byte block layout (known limit); the type comes from a list of base types.
mapheader-widened: struct MapHeader's map section is 32 bits in recipe 35: mapjson emits the header at that width and every generated header checks its size against MAP_HEADER_SIZE (patch series, ADMG-101's docs/admg101-dynamic-content.md).
rom-header: The RHH and Game Freak ROM headers describe the base build for external tools (fixed counts and lengths); the game does not read them for capacity.
not-a-registry: The value belongs to a kind that is not a content registry and keeps its range: stats, egg groups, growth rates, ability slot numbers, hold effects, move target flags and damage, contest categories, scores and excitement, map-section types, outbreak probabilities, link version signatures, fusion handling, movement types, random-generation option indices, relearner info category.
count: A count, total, quantity or size, bounded by the menu, list or table it counts, not a content ID.
slot-or-index: A move slot, party slot, list or menu index, or a cursor position, not a content ID.
bitmask: A bitmask over the four move slots or a restricted-move list (move limitations, known moves), not a content ID.
ui-state: Task and UI state: state machine values, timers, sprite and window IDs, fade parameters, camera-shake and confetti parameters, scroll-multichoice IDs, scores and list padding.
split-word: The low half of a function pointer kept across data[8] and data[9] (the high half is in data[8]), as the base game does.
boolean: A boolean result.
map-identity-widened: Recipe 37 makes the map one 32-bit MapId and the layout ID 32-bit in assembly-emitted structs on purpose (MapHeader, WarpEvent, MapConnection; the probe reads the former group and number members as the MapId): mapjson and the map.inc macros emit the new layouts and every generated header checks its size against MAP_HEADER_SIZE (ADMG-101's docs/admg101-f3.3a-map-identity.md).
fly-icon-mapsec: A Fly icon sprite keeps its map section in data[0] (s16): base sections are below MAPSEC_NONE and added sections start at FIRST_ADDED_MAPSEC (0x100); the SDK keeps added sections below 0x8000.
